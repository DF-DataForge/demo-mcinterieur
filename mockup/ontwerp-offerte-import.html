MC Interieur · module design

From Excel offer to project: mc_offer_import

A new Odoo module that reads MC Interieur’s Excel offer, built in the Bouwsoft structure of chapters, posts and text posts, and turns it into a project: the analysis, the furniture per room, and the questions that must be answered for that type of project. The TopSolid material list is added to the same project and checked against the offer.

Status: design, not built Depends on mc_interieur Structure: BouwsoftWaiting for: the offer template

The flow

Upload, check, create

The salesperson uploads the offer. Odoo reads it and shows a preview with anything it is unsure of. Only after confirmation does it create or update the project.

How the module recognises each line

  • Level from the code: 1 is a chapter, 1.1 a post, 1.1.1 a sub-post. No guessing from colours or fonts.
  • Text post: a line with a description but no code, quantity or price. Before the first chapter it is the project analysis; elsewhere a note at that place.
  • Furniture code: taken from the description (O1-O4, H1, E1) by a pattern set in Odoo, or from its own column if the template gets one.
  • Chapters that are not rooms (Plaatsing, Transport) are marked as services in the offer template record.
  • Columns are found by their header (Code, Omschrijving, Eenheid…), so an extra or moved column doesn’t break it.

What becomes what

  • Header: customer (matched to an existing contact), job-site address, offer number and date
  • Text post before chapter 1: the analysis of the project
  • Chapter: a room
  • Post: a furniture item, with code, description, size, finish, quantity and price
  • Sub-post: an option or detail of that furniture item
  • Service chapter: service lines (placement, transport), not furniture
  • The file itself: attached to the project as offer version 1, 2, …

One structure, three sources

Now Excel, during the migration Bouwsoft, later Odoo itself

Because the offer already follows the Bouwsoft structure, the same reader serves the migration too. After the switch to Odoo, offers are made directly in Odoo in the same structure, and the Excel import is no longer needed.

Now: Excel offer in Bouwsoft layout

  • Upload the Excel, preview, create the project
  • Works as long as offers are still made outside Odoo

Migration: open offers from Bouwsoft

  • The same reader takes Bouwsoft’s export of open offers
  • Each open offer becomes a project with rooms and furniture, without retyping

Later: offer made in Odoo

  • Same chapters, posts and text posts, as sections, lines and notes
  • The project, rooms and questions come straight from the Odoo quotation

What stays the same

  • Rooms, furniture, questions per type and the TopSolid check work the same, whatever the source
  • So the work done for the Excel import is not lost

Questions per project type

A checklist that blocks the next step

Each project type has its own list of questions, managed in Odoo. When a project is created from an offer, the questions for its type are added as open questions. A question can be marked as required before a stage: then the project cannot move on until it is answered.

How it fits what exists

  • Reuses the existing open questions and the portal, so customer questions still block approval
  • Reuses the intake: a question linked to an intake field is closed as soon as that field is filled
  • Conditional questions keep working (e.g. no architect → no “contact architect” question)

What is new

  • A checklist per project type, managed by a manager in Odoo
  • “Required before stage”: the stage button shows what is still missing
  • Progress on the project card: “6 / 8 vragen”

TopSolid material list

The drawing checked against the offer

The TopSolid list is imported with the existing import. Its cabinet column (Kast) is matched to the furniture code in the offer, so every furniture item knows its parts.

What the check shows

  • OK: furniture with parts
  • No parts: in the offer but not (yet) drawn
  • Not in the offer: parts with a cabinet code the offer doesn’t have, e.g. an extra cabinet added during drawing
  • Size differs: overall size from the parts differs strongly from the offer (tolerance to agree)

Why it helps

  • The drawer sees at once if something from the offer is missing
  • Sales sees if the drawing grew beyond the offer, before the final quote
  • The cabinet code becomes the common key from offer to label: the same code is on the TopSolid list, in Ardis and on every piece’s label

Decisions

To settle before building

Offer in Excel vs. quote from TopSolid

The current module calculates the final quote from the TopSolid material list. The Excel offer comes earlier, before the drawing. Proposal: treat the Excel offer as the first estimate (it starts the project and the questions), and keep the TopSolid-based quote as the final quote the customer approves with the drawing. After the Bouwsoft migration, the first estimate is made directly in Odoo in the same chapter and post structure.

  1. The offer template, plus one or two real offers in Bouwsoft layout (anonymised is fine)Decides the parser; the example above is an assumption.
  2. Does every line keep Bouwsoft’s code numbering (1, 1.1, 1.1.1)?The level of each line comes from that code. Without it, we need another fixed marker.
  3. Is a chapter always a room, and which chapters are services?Decides how chapters become rooms or service lines.
  4. Where is the analysis written: a text post before chapter 1, or elsewhere?Decides where the module takes the analysis from.
  5. Does every post contain a furniture code, and is it the same as the cabinet code in TopSolid?That is the key for the offer-vs-drawing check. If not, agree on a convention, or add a code column to the template.
  6. Which project types, and which questions per type?Start list to load as data; managers can change it later in Odoo.
  7. Should the offer already become an Odoo quotation (sections, lines, notes), or stay information only until the migration?See the box above.
  8. What happens to a new offer version: replace the furniture, or show the differences first?Proposal: show added, removed and changed lines, then apply.

Building it

Phases

phase 1

Read the offer

Template record for the Bouwsoft layout, parser with openpyxl (already in Odoo), preview wizard, project with analysis and furniture per room, offer file as version. Tests with the real offers in CI.

phase 2

Questions per type

Question templates per project type, required-before-stage, progress on the project, portal for customer questions.

phase 3

Check against TopSolid

Match parts to furniture by cabinet code, check status and size, overview for drawer and sales.

phase 4

Versions and migration

Differences between offer versions; the same reader for the open offers from Bouwsoft; after the migration, projects straight from an Odoo quotation in the same structure.

Technical: separate module mc_offer_import depending on mc_interieur; reads .xlsx with openpyxl; Dutch UI like the rest; access rights like the project (sales and managers import, drawers read).

Design for MC Interieur. The offer follows the Bouwsoft structure; the exact layout and all example content are assumptions until the offer template is available.
